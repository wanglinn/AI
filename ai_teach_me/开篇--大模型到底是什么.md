## 第 0 课：大模型到底是什么？

### 0.1 先破除一个错觉

很多人以为大模型是：
- ❌ 一个巨大的搜索引擎（不是查数据库）
- ❌ 一个规则引擎（不是 if-else 写死的）
- ❌ 一个真正"理解"人类的人（没有意识）

**真相**：大模型是一个**超级概率预测机**。它只做一件事——**给定前面的文字，预测下一个最可能出现的词**。

就像你手机输入法的自动补全，但聪明一亿倍。

### 0.2 核心机制：预测下一个 Token

想象这个场景：

> 你输入："数据库内核开发需要掌握______"

你的大脑会猜：
- 60% 可能：操作系统
- 25% 可能：数据结构  
- 10% 可能：C++
- 5% 可能：做饭

**大模型做的就是这件事**，但它读过互联网上几乎所有的文字，所以它的"直觉"极其精准。

**关键洞察**：它**不是**先理解再回答，而是**一边预测一边生成**。生成第一个词后，把这个词加到输入里，再预测第二个词，如此循环。

这就是为什么它有时会"胡说八道"——它只是在预测"像人话的内容"，而不是查事实。

### 0.3 和你熟悉的数据库对比

| 数据库系统 | 大模型 |
|---|---|
| 存储确定的数据（行/列） | 存储压缩的"知识模式"（权重） |
| 查询返回精确结果 | 生成概率性结果 |
| SQL 明确告诉它做什么 | Prompt 只是"提示"，它自己猜 |
| 有索引加速 | 有 Attention 机制关联信息 |

**类比**：如果数据库是**图书馆**（存什么取什么），大模型就是**一个读过图书馆所有书的人**（能复述、总结、改写，但可能记错细节）。

### 0.4 参数：模型的"脑细胞数量"

你说你有 7B 模型，这个 **7B = 70 亿个参数**。

- **参数**就是模型内部的数字（权重），类似人脑神经元连接的强度
- 这些数字不是人工设置的，是**训练**出来的
- 7B 意味着文件里有 70 亿个浮点数，大概占 4GB~16GB 磁盘（看精度）

**直觉**：参数越多，能记住的模式越复杂，但也越吃内存。

### 0.5 训练 vs 推理（最重要的区分）

| 阶段 | 做什么 | 类比 | 你的 Qwen 在做什么 |
|---|---|---|---|
| **训练** | 调整 70 亿个参数，让预测更准确 | 学生上课学习 | ❌ 你没做，别人做好了 |
| **推理** | 用固定好的参数做预测 | 学生考试答题 | ✅ 你正在做的 |

你本地的 Ollama 只是**推理引擎**，就像数据库的查询执行器，不负责"教"模型，只负责"跑"模型。

## 🔬 今天的小实验（5 分钟）

打开终端，我们观察"预测下一个词"的原始形态：

```bash
ollama run qwen2.5:7b
```

然后输入这三句话，观察它的反应：

**实验 1：补全模式**
```
请只补全下面这句话，不要解释，不要加任何其他内容：
"在关系型数据库中，索引通常使用"
```
*（按 Ctrl+D 或输入 /bye 退出）*

**你会看到**：它可能会输出 `B+ 树` 或 `B+ Tree`，然后停下来。这就是"预测下一个词"——它认为这里最该出现这个词。

**实验 2：观察概率性**
```
用一句话解释什么是事务
```

**再运行一次同样的命令**，你会发现回答可能不一样。这就是**采样**——它从概率分布中随机选词，不是查固定答案。

**实验 3：感受"幻觉"**
```
请告诉我《数据库系统概念》这本书第 12 章第 3 节的标题是什么？
```

它很可能会编一个看似合理但错误的答案。这不是 bug，这是**生成式模型的本质**——它在预测"像章节标题的文字"，而不是在查书。
