## 第 2 课：Embedding —— 给文字编坐标

### 2.1 一个魔法现象

先做个思想实验。如果让你用两个数字来表示一个城市，你会怎么编？

- 北京：(0.9, 0.1) —— 政治中心，北方
- 上海：(0.1, 0.9) —— 经济中心，南方  
- 东京：(0.2, 0.8) —— 经济中心，东方

现在计算：**北京 - 上海 + 东京** = (0.9-0.1+0.2, 0.1-0.9+0.8) = (1.0, 0.0)

这个结果可能对应"某个政治中心但不在南北轴上"——比如**华盛顿**。

**这就是 Embedding 的直觉**：**用数字的"距离"和"方向"来表示语义关系**。

---

### 2.2 什么是 Embedding？

**Embedding（嵌入）就是把离散的 Token 变成连续的向量（一串数字）**。

| Token | Embedding（简化示例，实际可能是 4096 维） |
|---|---|
| 猫 | [0.2, 0.8, -0.3, ...] |
| 狗 | [0.3, 0.7, -0.2, ...] |
| 汽车 | [-0.9, 0.1, 0.5, ...] |

**关键特性**：
1. **语义相近的词，向量距离近**："猫"和"狗"的向量距离 < "猫"和"汽车"
2. **语义关系可以计算**："国王" - "男人" + "女人" ≈ "皇后"（这是真实存在的现象）

---

### 2.3 为什么需要 Embedding？

回顾第 1 课：Token 是**离散的符号**（就像数据库的主键 ID），本身没有语义。

- Token "北京" = 编号 12345
- Token "首都" = 编号 54321

这两个编号**没有任何数学关系**。但模型需要计算"北京"和"首都"有多相关，怎么办？

**Embedding 就是"查表"**：
- 模型内部有一个巨大的**嵌入矩阵**（Embedding Matrix）
- 大小：词汇表 × 向量维度（如 50000 × 4096）
- 输入 Token ID，输出对应的向量

**类比数据库**：
- 就像你有一个 `word_id → feature_vector` 的映射表
- 但这个表不是人工设计的，是**训练出来的**
- 训练目标：让经常一起出现的词，向量距离更近

---

### 2.4 向量空间：语义的几何表示

想象一个 3D 空间（实际可能是 4096 维，但 3D 好想象）：

- **方向**表示语义关系：
  - 从"男人"指向"女人"的方向 ≈ 从"国王"指向"皇后"的方向（性别维度）
  - 从"北京"指向"上海"的方向 ≈ 从"中国"指向"美国"的方向（国家维度）

- **距离**表示相似度：
  - "数据库" 和 "MySQL" 距离近
  - "数据库" 和 "香蕉" 距离远

**这就是语义搜索的基础**：不是匹配关键词，而是匹配**向量距离**。

---

### 2.5 Embedding 与数据库索引的对比

| 数据库索引 | Embedding 向量索引 |
|---|---|
| B+ Tree：精确匹配 | HNSW：近似最近邻（ANN） |
| 查询 "name = '北京'" | 查询 "语义接近 '北京' 的文档" |
| O(log N) 精确查找 | O(log N) 近似查找，可能漏掉个别结果 |
| 适合结构化数据 | 适合非结构化数据（文本、图片、音频） |

**关键区别**：数据库索引是**精确**的，向量索引是**近似**的（ANN）。为什么用近似？因为在高维空间（4096 维）做精确最近邻搜索太慢，近似算法快 1000 倍，精度损失只有 1%~2%。

## 🔬 今天的小实验（15 分钟）

### 实验 1：观察 Embedding 的实际效果

我们需要用 Python 调用 Ollama 的 API（不是命令行，因为命令行不直接显示向量）。

创建文件 `embedding_demo.py`：

```python
import ollama
import numpy as np

# 获取 embedding
def get_embedding(text):
    response = ollama.embeddings(model='qwen2.5:7b', prompt=text)
    return np.array(response['embedding'])

# 测试几个词
words = ["北京", "上海", "广州", "数据库", "MySQL", "香蕉"]
embeddings = {w: get_embedding(w) for w in words}

# 计算余弦相似度（向量夹角的余弦值，1 表示完全相同，0 表示无关）
def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# 对比
print("=== 语义相似度对比 ===")
print(f"北京 vs 上海: {cosine_similarity(embeddings['北京'], embeddings['上海']):.3f}")
print(f"北京 vs 数据库: {cosine_similarity(embeddings['北京'], embeddings['数据库']):.3f}")
print(f"数据库 vs MySQL: {cosine_similarity(embeddings['数据库'], embeddings['MySQL']):.3f}")
print(f"数据库 vs 香蕉: {cosine_similarity(embeddings['数据库'], embeddings['香蕉']):.3f}")
```

**运行**：
```bash
python embedding_demo.py
```

**你会看到**：
- "数据库" 和 "MySQL" 的相似度 > 0.7（很相关）
- "数据库" 和 "香蕉" 的相似度 < 0.3（几乎无关）
- "北京" 和 "上海" 的相似度中等（都是城市，但不同地方）

### 实验 2：观察"语义运算"

```python
# 经典测试：国王 - 男人 + 女人 ≈ 皇后
king = get_embedding("国王")
man = get_embedding("男人")
woman = get_embedding("女人")
queen = get_embedding("皇后")

result = king - man + woman
print(f"国王-男人+女人 vs 皇后: {cosine_similarity(result, queen):.3f}")
print(f"国王-男人+女人 vs 国王: {cosine_similarity(result, king):.3f}")
```

**通常结果**：结果向量与"皇后"的相似度 > 与"国王"的相似度。这就是**语义关系被编码在向量方向中**的证据。

### 实验 3：观察维度

```python
# 看看 embedding 的实际维度
print(f"向量维度: {len(embeddings['北京'])}")
print(f"前 10 个数值: {embeddings['北京'][:10]}")
```

**你会看到**：一个 4096 维（或 3584 维，取决于 Qwen 版本）的浮点数数组。这就是"北京"在模型眼中的"坐标"。

## 📊 Embedding 与数据库的深层类比

| 数据库概念 | Embedding 概念 | 你的理解优势 |
|---|---|---|
| 特征工程（人工设计列） | 表示学习（自动学习特征） | 你懂人工特征 vs 自动特征的区别 |
| 列存数据库（每列是一个维度） | 向量维度（每个维度是一个特征） | 都是高维空间中的点 |
| 聚簇索引（物理上按索引存储） | 向量索引（HNSW 图结构） | 都是加速查找的数据结构 |
| SQL 的 ORDER BY 距离 | 向量检索的 Top-K | 都是"找最近的" |

**关键洞察**：传统数据库需要你先**显式定义** schema（列名、类型），而 Embedding 是**隐式**的——模型自动学会"哪些维度重要"，人类不可解释。这就是为什么叫"黑盒"。
