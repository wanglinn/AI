## 第 3 课：Attention —— 让模型"看上下文"的眼睛

### 3.1 先解决上节课的矛盾

上节课留了一个问题：**"苹果"在"吃水果"和"用手机"中，Token 相同但 Embedding 相同，怎么区分？**

**答案**：靠 **Attention（注意力）**。

Embedding 只是**静态**的"底子"（苹果的基础语义），Attention 是**动态**的"语境调整器"——它根据周围的词，实时调整"苹果"在这个句子里的"含义权重"。

---

### 3.2 一个生活类比

想象你在读这句话：

> "我把苹果放在盘子里，因为它很甜"

你看到"它"时，怎么知道指的是"苹果"而不是"盘子"？

**你的大脑自动做了两件事**：
1. **回顾**：扫一眼前面的词（苹果、盘子）
2. **加权**：判断"苹果"和"甜"的关联更强，"盘子"和"甜"的关联弱

**这就是 Attention 的机制**：
- **Q (Query)**：当前词在"问"——"我需要什么样的信息？"
- **K (Key)**：每个前面的词在"答"——"我能提供什么信息？"
- **V (Value)**：实际传递的信息内容

**计算过程**：
1. "它"的 Q 向量 分别和 "苹果"、"盘子" 的 K 向量做点积（相似度计算）
2. 得到分数：Q·K苹果 = 0.9，Q·K盘子 = 0.1
3. 用 softmax 归一化：变成权重 [0.9, 0.1]
4. 加权求和：0.9 × V苹果 + 0.1 × V盘子 = "它"的新表示

**结果**："它"的向量现在**融合了"苹果"的信息**，而不是孤立的"它"。

---

### 3.3 数据库视角：Attention 就是 JOIN

| SQL 操作 | Attention 操作 |
|---|---|
| `SELECT * FROM context WHERE relevance > threshold` | 计算 Q·K 相似度，筛选重要信息 |
| `ORDER BY similarity DESC LIMIT k` | Softmax 归一化，权重大的关注多 |
| `JOIN` 两个表，取匹配行的字段 | 加权求和 V，融合不同位置的信息 |
| 索引加速查找 | 矩阵乘法加速并行计算 |

**关键洞察**：
- 没有 Attention 的模型：像 **MapReduce**，每个词独立处理，看不到上下文
- 有 Attention 的模型：像 **Hash Join**，每个词都能"关联"到其他词

---

### 3.4 为什么叫"自注意力"（Self-Attention）？

因为 **Q、K、V 都来自同一个句子**——句子自己在关注自己。

对比数据库：
- 普通 JOIN：两张不同的表关联（用户表 JOIN 订单表）
- Self-Attention：**同一张表自关联**（每个词和其他所有词算相似度）

这就是为什么 Transformer 是"自回归"的——它通过自我关注来理解语境。

---

### 3.5 多头注意力：多个角度的理解

不是只做一次 Attention，而是做 **N 次（通常 12~32 次）**，每次用不同的权重矩阵。

**类比数据库**：
- 一次 Attention：用一个条件 JOIN（WHERE type = 'fruit'）
- 多头 Attention：用多个条件同时 JOIN（一个是语义相关性，一个是语法结构，一个是情感色彩...）

**结果**：模型能从**不同维度**理解"苹果"：
- 头 1：关注"苹果"是水果（语义）
- 头 2：关注"苹果"是主语（语法）
- 头 3：关注"苹果"是品牌（语境）

## 🔬 今天的小实验（20 分钟）

### 实验 1：观察 Attention 权重（需要代码）

创建 `attention_demo.py`：

```python
import ollama
import numpy as np

# 由于 Ollama 不直接暴露 attention 权重，我们用"探针"法测试
# 通过遮挡（masking）来观察模型对上下文的依赖

def get_embedding(text):
    response = ollama.embeddings(model='qwen2.5:7b', prompt=text)
    return np.array(response['embedding'])

# 测试 1：上下文如何改变语义
sentence1 = "苹果很好吃，我喜欢吃苹果"
sentence2 = "苹果发布了新手机，我买了很多苹果股票"

# 提取最后一个词的 embedding（代表整句理解）
emb1 = get_embedding(sentence1)
emb2 = get_embedding(sentence2)

# 对比"苹果"相关词的相似度
apple_food = get_embedding("水果")
apple_tech = get_embedding("科技公司")

print("=== 上下文影响测试 ===")
print(f"句子1 vs 水果: {np.dot(emb1, apple_food):.3f}")
print(f"句子1 vs 科技公司: {np.dot(emb1, apple_tech):.3f}")
print(f"句子2 vs 水果: {np.dot(emb2, apple_food):.3f}")
print(f"句子2 vs 科技公司: {np.dot(emb2, apple_tech):.3f}")
```

**你会看到**：句子 1 的整句向量更接近"水果"，句子 2 更接近"科技公司"——**Attention 机制根据上下文调整了语义**。

### 实验 2：观察长距离依赖

```bash
ollama run qwen2.5:7b
```

输入：

```
请阅读下面这段话，然后回答问题：

```

### 实验 3：注意力分散（幻觉的来源）

```bash
>>> "猫坐在垫子上，因为它很累。它是什么动物？"
```

模型可能答"猫"（正确），也可能答"垫子"（错误）。**为什么？**

因为 "它" 的 Q 向量可能同时和 "猫"、"垫子" 的 K 向量有较高相似度。如果训练数据里"垫子"经常和"累"共现，模型可能被误导。

**这就是幻觉的本质**：Attention 权重分配错误，导致关注了错误的上下文。

## 📊 Attention 计算详解（给内核开发者的深入版）

### 3.6 计算流程（矩阵化）

假设序列长度 n，维度 d：

1. **线性变换**：X × Wq = Q，X × Wk = K，X × Wv = V
   - 三个可学习矩阵，类似数据库的三个索引

2. **相似度计算**：Q × K^T / √d = S
   - n × n 的矩阵，每个元素是位置 i 和 j 的关联度
   - 除以 √d 是数值稳定性技巧（防止 softmax 饱和）

3. **归一化**：Softmax(S) = A（按行归一化）
   - 每行和为 1，表示"当前词应该关注前面所有词的比例"

4. **加权求和**：A × V = O
   - 输出是 Value 的加权和，即"融合上下文后的新表示"

**复杂度**：O(n² × d)
- n² 是因为每个词都要和所有词算相似度（类似全表扫描）
- 这就是长文本推理慢的原因（第 6 课会讲 KV Cache 优化）
